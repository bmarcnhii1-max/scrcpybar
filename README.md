# 🎮 Scrcpy Music — виджет для Xbox Game Bar

Виджет для оверлея **Xbox Game Bar** (`Win + G`), который в реальном времени показывает играющий трек с Android-смартфона и управляет им прямо во время игры. Метаданные и обложки идут через **Android companion app** по USB, поэтому работают надёжно и быстро — без разбора UI, скриншотов и `cmd media_session`.

---

## 📁 Структура проекта

| Проект | Назначение |
|---|---|
| **`ScrcpyBar.Android/`** | Kotlin-приложение на телефоне (`com.scrcpybar.companion`). Читает `MediaSessionManager` через `NotificationListenerService`, отдаёт JSON-API и принимает команды. Требует только разрешение «Доступ к уведомлениям» — без root, без accessibility, без UI-автоматизации. |
| **`ScrcpyBar.Bridge/`** | Фоновая служба .NET 8. Опрашивает companion по USB-туннелю, кеширует обложки и слова песни, отдаёт HTTP-API и публикует сессию в **Windows Media Controls (SMTC)**. |
| **`ScrcpyBar.Widget/`** | Виджет Xbox Game Bar (UWP XAML + `Microsoft.Gaming.XboxGameBar`). Тёмный минималистичный оверлей: обложка, название, исполнитель, перемотка мышью, кнопки ⏮ ⏯ ⏭, громкость. |
| **`ScrcpyBar.sln`** | Файл решения для Visual Studio 2022. |

### Скрипты

| Файл | Назначение |
|---|---|
| **`rebuild_and_deploy.ps1` / `.bat`** | Пересборка виджета + регистрация пакета + loopback-exemption. Один клик. |
| **`verify.ps1`** | Сквозная проверка стека: companion → Bridge → HTTP-API → SMTC → виджет. По умолчанию read-only, `-Transport` включает проверки с нажатием кнопок. |
| **`check_smtc_sessions.ps1`** | Диагностика: все SMTC-сессии системы, метаданные, обложка. |
| **`check_widget_log.ps1`** | Лог событий указателя виджета (диагностика перемотки). |
| **`check_lyrics_flow.ps1`** | Прогон сценария слов песни ровно так, как его делает виджет. |
| **`ScrcpyBar.Widget\Assets\generate_logo.ps1`** | Перегенерация иконок и заставок. |
| **`start_bridge.bat`** | Запуск Bridge. |
| **`open_in_vs.bat`** | Открыть решение в Visual Studio 2022. |

## 🔌 Как это связано (только USB)

```
Android: companion app  127.0.0.1:38080   (сервер биндится только на loopback телефона)
              │
              │  adb forward tcp:39282 tcp:38080
              ▼
PC:       Bridge         http://127.0.0.1:39281   (API + веб-пульт + SMTC)
              │
              ▼
         Widget (Win + G)   →  http://127.0.0.1:39281
```

Телефон доступен **только по USB**. Ни Wi-Fi, ни интернет, ни внешние порты не используются — companion слушает `127.0.0.1` на самом телефоне, наружу его пробрасывает `adb forward`. Авторизация по умолчанию выключена, потому что трафик физически не покидает USB-кабель.

### Архитектура доступа к медиа

1. **Основной путь** — companion app: `MediaSessionManager.getActiveSessions()` даёт трек, позицию, длительность, скорость, обложку и список доступных действий (`play`, `pause`, `next`, `previous`, `seek`). Команды уходят через `MediaController` — это штатный Android API.
2. **Fallback** — если companion недоступен, Bridge читает `adb shell dumpsys media_session` и управляет плеером тапами по координатам (`uiautomator`). Он медленнее и не умеет точную перемотку, поэтому включается только как страховка.

### Когда телефонов два

Bridge работает с **одним** телефоном — тем, что указан в `ScrcpyBar.Bridge\device.txt`. Файл приходит пустым: тогда Bridge берёт первый доступный из `adb devices`.

Чтобы закрепить конкретный телефон, напиши его серийник (или начало — подойдёт любой префикс):

```
a1b2c3d4
```

Альтернатива — переменная окружения `SCRCPYBAR_DEVICE` (имеет приоритет над файлом).

Второй телефон, подключённый параллельно, просто игнорируется: управление, обложка, слова и громкость всегда идут на выбранный. Все команды adb выполняются с `-s <serial>`, поэтому телефоны не путаются.

## ⚙️ Подготовка (один раз)

Виджеты Xbox Game Bar собираются на UWP. Нужен компонент Visual Studio:

1. **Пуск** → **Visual Studio Installer** → **Изменить**.
2. Рабочие нагрузки → ☑️ **Разработка приложений для универсальной платформы Windows**.
3. Убедиться, что справа выбран Windows 10/11 SDK → **Изменить**.

На телефоне: включить **Отладка по USB** и выдать companion приложению разрешение **«Доступ к уведомлениям»** (приложение само предложит экран настроек при первом запуске).

## 📦 Готовые сборки (без Visual Studio)

Папка [`build/`](build/) содержит уже собранные артефакты. Телефону нужен только APK, компьютеру — Bridge и MSIX:

| Файл | Что это |
|---|---|
| `ScrcpyBar.Bridge.exe` | **Главный файл.** Один exe: рантайм, виджет msix+cer, companion apk — всё внутри. Запуск двойным кликом. |
| `ScrcpyBar.Companion-1.0.0.apk` | Companion отдельным файлом (на случай ручной установки на телефон). |
| `ScrcpyBar.Widget-1.0.0.msix` + `.cer` | Виджет отдельными файлами (на случай ручной установки). |
| `install-widget.ps1` | Ручная установка виджета одним скриптом (сертификат → регистрация → loopback). |

**Достаточно одного `ScrcpyBar.Bridge.exe`:** при первом запуске окно «Первоначальная настройка» само предложит поставить виджет (один запрос UAC) и companion на телефон через USB. Позже окно доступно из меню трея — «Первоначальная настройка…». Отдельные файлы сверху — запасной вариант.

Пересобрать всё свежим можно так: компаньон — `gradlew.bat assembleDebug` в `ScrcpyBar.Android\`; виджет — `rebuild_and_deploy.ps1`; Bridge — `dotnet publish ScrcpyBar.Bridge -c Release -r win-x64` (одиночный exe; apk/msix/cer/рантайм/`silence.wav` встраиваются, если найдены собранные артефакты).

> ⚠️ Сертификат в `ScrcpyBar_TestCert.pfx` — тестовый (пароль `1234`). Живёт только для локальной установки; свои сертификаты для downstream-сборок генерятся в свойствах проекта виджета.

## 🚀 Запуск

### Шаг 1. Установить и запустить companion на телефоне

```bash
cd ScrcpyBar.Android
gradlew.bat assembleDebug
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

Запусти приложение **ScrcpyBar Companion** на телефоне, убедись, что переключатель сервера включён, а статус — **running**. Выдай доступ к уведомлениям, если попросит.

### Шаг 2. Поднять туннель и Bridge

Проще всего запустить `ScrcpyBar.Bridge.exe` двойным кликом — это **один файл без зависимостей** (.NET 8 встроен, `silence.wav` тоже внутри):

- **Окна и консоли не будет** — служба работает в фоне.
- Появится **значок в трее**: статус работы, «Открыть пульт», галочка **«Запускать при входе в Windows»**, выход.
- **Двойной клик** по значку — веб-пульт.
- Логи пишутся в `%LOCALAPPDATA%\ScrcpyBar\bridge.log` (ротация на 5 МБ, старый файл — `bridge.old.log`). Кеши обложек (`cover-cache`) и слов (`lyrics-cache`) тоже живут там, так что exe можно положить в `C:\Program Files` или на флешку — писать рядом с ним ничего не нужно.
- Дополнительно можно создать рядом с exe файл `device.txt` с серийником телефона — пользовательская настройка, exe её читает, но не требует.

Из консоли для отладки:

```bash
adb forward tcp:39282 tcp:38080
start_bridge.bat        # тот же Bridge в режиме --console
ScrcpyBar.Bridge.exe --console
```

Bridge сам выполнит `adb forward` при старте, но ручная команда не помешает. Повторный запуск exe не откроет вторую копию — покажет «уже запущен» и закроется.

> 💡 Открой `http://127.0.0.1:39281` — там веб-пульт с живым треком, прогрессом и обложкой.

### Шаг 3. Задеплоить виджет

Проще всего:

```powershell
.\rebuild_and_deploy.ps1
```

Скрипт пересоберёт виджет, распакует MSIX, перерегистрирует пакет и выдаст loopback-exemption (без него UWP-виджет не достучится до `127.0.0.1`). Либо вручную: `open_in_vs.bat` → правой кнопкой по `ScrcpyBar.Widget` → **Развернуть**.

### Шаг 4. Пользоваться

1. **`Win + G`** → иконка виджетов → **Scrcpy Music**.
2. Кнопка **булавки** закрепляет виджет поверх игры.
3. По полосе прогресса можно **перематывать мышью** — отпусти, и трек перейдёт на выбранную позицию.
4. Работают также **клавиши Windows Media** и панель **Windows Media Controls** (`Win + ↑`).

### Караоке: слова песни

Кнопка **«Текст»** в шапке виджета переключает панель с **синхронными словами** — текущая строка подсвечивается по ходу трека, уже спетое выделяется белым, остальное гаснет. Слова берутся с [lrclib.net](https://lrclib.net) (бесплатный API, без ключа) и кешируются на диске, поэтому один и тот же трек больше не запрашивается из сети.

Если синхронных слов нет — показывается обычный текст песни. Если трек инструментальный — соответствующая подпись.

### Переход по клику

Нажми на **любую** строку в панели слов (текущую, предыдущую или следующую) — трек перемотается на ту секунду, где начинается эта строка. Удобно, когда играет бэк-трек, а нужная строка ещё впереди: можно сразу прыгнуть на неё, не тядя полосу прогресса.

Подсветка идёт плавно: текущая строка рисуется градиентной кистью, у которой двигается резкая граница между спетым и неспетым. Сам текст при этом не перевёрстывается, поэтому ничего не дёргается.

## 🔌 API Bridge

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/track` | Текущий трек, позиция, длительность, обложка |
| `GET` | `/api/cover` | JPEG/PNG обложки текущего трека |
| `GET` | `/api/lyrics` | Слова песни с lrclib.net (`linesText` — строки `timeMs<TAB>текст`) |
| `POST` | `/api/play-pause` | Пауза / воспроизведение |
| `POST` | `/api/next` · `/api/prev` | Следующий / предыдущий трек |
| `POST` | `/api/seek?seconds=±N` | Перемотка относительно (шаг ±300 с) |
| `POST` | `/api/seek-position?positionMs=&durationMs=` | Точная перемотка |
| `POST` | `/api/rewind` · `/api/fast-forward` | Короткая перемотка ±5 с |
| `POST` | `/api/vol-up` · `/api/vol-down` · `/api/volume?level=N` | Громкость |
| `GET` | `/` | Веб-пульт |

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/health` | Живость, версия, состояние listener'а |
| `GET` | `/state` | Снимок основной сессии |
| `GET` | `/sessions` | Все активные сессии |

## ✅ Проверка работоспособности

```powershell
powershell -ExecutionPolicy Bypass -File .\verify.ps1
```

По умолчанию скрипт **ничего не нажимает** — только read-only проверки: доступность companion и listener'а уведомлений, HTTP-API, отдачу обложки, публикацию SMTC-сессии с метаданными и обложкой, регистрацию виджета с loopback-exemption.

Полный прогон (31 проверка) дополнительно жмёт play/pause, переключает треки и перематывает — **это прерывает музыку на телефоне**, поэтому включается флагом:

```powershell
powershell -ExecutionPolicy Bypass -File .\verify.ps1 -Transport
```

### Диагностика ввода в виджете

Game Bar не даёт виджету консоль, поэтому виджет пишет события указателя в файл:

```powershell
powershell -ExecutionPolicy Bypass -File .\check_widget_log.ps1
```

Покажет `pointerPressed` (результат захвата, координату, ширину трека) и `seek response status=200`. Пустой лог означает, что события указателя не доходят до виджета.

## 📱 Поддерживаемые плееры

Любое приложение с активной `MediaSession`. Проверено на YouTube Music; поддерживаются Spotify, Яндекс Музыка, VK Музыка, SoundCloud, Apple Music, Deezer и любые системные плееры Android.

> ⚠️ Некоторые плееры не отдают обложку через `MediaSession` — тогда виджет покажет иконку музыкальной ноты, а остальные поля работают как обычно.

## 🐛 Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| `Мост офлайн` в виджете | Не запущен Bridge. Проверь `start_bridge.bat`. |
| `Нет телефона` | Телефон не в `adb devices`. Переподключи кабель, включи отладку по USB. |
| `Нет доступа к медиа` | Companion без разрешения на уведомления. Открой приложение и выдай доступ. |
| Пустое поле обложки | Плеер не отдаёт обложку через MediaSession — это нормально, остальное работает. |
| Виджет не видит Bridge | Не выполнен `CheckNetIsolation LoopbackExempt`. `rebuild_and_deploy.ps1` делает это сам. |
| Логи Bridge | `%LOCALAPPDATA%\ScrcpyBar\bridge.log` (консольный режим — `ScrcpyBar.Bridge.exe --console`). |
| Значок в трее не появился | Bridge падал при старте — лог скажет причину (обычно порт 39281 занят или .NET SDK некорректен). |
